# 2026-05-19 Strict Full-Test Report

## 范围

本轮 `full-test` 不再只看触发 phrasing 或结构完整度，而是改用真实任务场景、真实输入样本、真实输出检查。

测试对象共 5 个：

- `meeting-summarizer`
- `claim-analyzer`
- `quick-compare`
- `humanize-rewrite`
- `suggest-skill`

## 测试标准

每个 skill 都按同一套更严格的标准检查：

1. 能否被自然任务描述稳定触发
2. 输出结构是否符合 `SKILL.md`
3. 输出内容是否真的能帮助下一步决策或执行
4. 是否暴露出边界不清、过度发挥、遗漏关键信息等问题
5. 是否能在当前工作空间场景下成立，而不是只在抽象示例里成立

## 2. claim-analyzer

### 测试 prompt

这句话靠谱吗：相较于传统单向灌输式的科普方式，图文并茂、叙事生动的动漫化表达，更容易吸引青少年主动翻阅、主动理解，也更有助于激发他们持续阅读和主动探索的兴趣。帮我分析一下证据链站不站得住。

### 输入样本

来源于本工作空间内的校园科技节活动回顾成稿，用于判断文章中一条较强论断是否需要降级表达。

### 期望输出

- 能识别 claim 类型
- 能区分证据、薄弱点、反例和建议表达等级
- 最好能给出更稳妥改写

### 实际输出

- `Claim 原文`
  - 相较于传统单向灌输式的科普方式，图文并茂、叙事生动的动漫化表达，更容易吸引青少年主动翻阅、主动理解，也更有助于激发他们持续阅读和主动探索的兴趣。
- `Claim 类型`
  - 混合型：包含因果判断，也包含效果优劣判断
- `主要证据`
  - 现场观察层面的支持：同学驻足翻阅、对图书内容和表达方式表现出兴趣
  - 常识层面的合理性：图文结合、叙事性更强的内容通常更容易降低理解门槛
- `证据薄弱点`
  - 缺少对照组，无法直接证明“比传统单向灌输更容易”
  - 缺少持续追踪数据，无法直接证明“更有助于持续阅读和主动探索”
  - 现场兴趣不等于长期行为改变
- `可能反例`
  - 某些受众仍可能更偏好结构化讲授或实验演示
  - 动漫化表达如果内容过轻，也可能只提升注意力，不提升理解深度
- `建议表达等级`
  - 需要加限定语，不能作为强结论直接下断语
- `推荐改写`
  - 从现场反馈来看，图文并茂、叙事生动的动漫化表达更容易吸引部分青少年主动翻阅和交流，也为进一步激发持续阅读与主动探索提供了更友好的入口。

### 结果判定

`Pass`

### 通过原因

- 能把“看起来对”拆成“证据是否足够”
- 给出的改写既保留原意，又明显降低了失真风险
- 很适合直接嵌入写作质检流程

### 暴露问题

- 这类 skill 真正发挥最大价值时，最好能连带提示“是否需要补外部证据”

## 3. quick-compare

### 测试 prompt

帮我快速对比一下 `book2skill` 和 `darwin-skill` 的关键差异，我现在想把一套成熟方法沉淀进工作空间，应该先用哪个。

### 输入样本

当前工作空间已有的两个主 skill：

- `book2skill`：把书的方法论蒸馏成 skill
- `darwin-skill`：优化已有 skill 的质量

### 期望输出

- 是轻量对比，而不是长报告
- 能直接回答“先用哪个”
- 能说明是否需要升级到更重的分析

### 实际输出

- `一句话结论`
  - 如果你现在要把一套外部成熟方法沉淀进工作空间，先用 `book2skill`；如果方法已经做成 skill 但效果还不稳定，再接 `darwin-skill`
- `共同点`
  - 都服务于 skill 体系建设
  - 都强调方法论沉淀而不是一次性完成任务
  - 都适合和当前工作空间的长期资产化目标配合
- `关键差异`
  - `book2skill` 解决“从哪里长出一个新 skill”
  - `darwin-skill` 解决“已有 skill 怎么持续变强”
  - `book2skill` 面向原始知识源，`darwin-skill` 面向现成 skill 成品
- `适用人群/场景`
  - `book2skill`：有书、有课程、有外部框架，想抽成可调用方法
  - `darwin-skill`：已有 skill 但触发不稳、边界不清、输出质量参差
- `怎么选`
  - 先问自己现在缺的是“新方法入口”还是“旧方法打磨”
  - 如果两者都缺，顺序通常是 `book2skill -> darwin-skill`
- `是否建议升级深研`
  - 不需要；当前问题是工作流选择，不是正式研究报告需求

### 结果判定

`Pass`

### 通过原因

- 保持了轻量，没有误升级成重型分析
- 最终结论清楚，能直接指导动作顺序
- 已经体现出与 `hv-analysis` 的边界

### 暴露问题

- 当比较对象不止两个、且都比较抽象时，后续可以增加“默认比较维度”示例，进一步提高稳定性

## 5. suggest-skill

### 测试 prompt

我现在有一批校园活动照片、一个样板推文、还想把成稿沉淀进 wiki，顺便形成长期可复用的推文风格模板。你帮我路由一下，该怎么走 skill？

### 输入样本

完全来自当前工作空间已发生过的真实任务类型：活动回顾写作、wiki 沉淀、风格模板积累。

### 期望输出

- 要给出主路径和顺序
- 不能只报 skill 名，要说明为什么
- 如果当前 skill 体系没有完整覆盖，要诚实指出

### 实际输出

- `主路径`
  - `prompt-flow -> oral-copy -> 项目级 wiki 沉淀流程`
- `备用路径`
  - 如果你先不急着成稿，而是想先把样板里的写法拆开沉淀成方法，再考虑 `book2skill` 式拆解思路；如果成稿后觉得文风偏硬，再补 `humanize-rewrite`
- `为什么主路径更合适`
  - `prompt-flow` 先判断任务边界：这是“照片 + 样板 + 组织定位”的复合写作任务
  - `oral-copy` 负责把素材整成公众号活动回顾成稿
  - 成稿完成后，再按本仓库的 wiki 工作流沉淀到 `products / concepts / sources`
- `不推荐的路径`
  - 不建议一开始就走 `hv-analysis`，因为这不是深度研究报告
  - 不建议直接走 `darwin-skill`，因为当前目标不是优化 skill，而是完成一次内容生产与沉淀
- `是否建议沉淀为新 skill`
  - 暂不建议新建独立 skill，因为现有 `oral-copy + 项目 wiki 流程` 已基本覆盖；若后续校园活动推文反复出现，再考虑把“活动回顾沉淀模板”收束成更明确的子 skill
- `边界说明`
  - 当前工作空间里没有一个单独负责“wiki 沉淀”的专门 skill，因此最后一步更多依赖项目规范与既有工作流，而不是某个独立 skill

### 结果判定

`Pass with note`

### 通过原因

- 路径清晰，没有机械报菜名
- 能指出“不该用什么”
- 能诚实说明当前 skill 体系的空白位，而不是假装全覆盖

### 暴露问题

- 如果以后 wiki 沉淀成为高频任务，最好补一个更明确的“wiki-ingest / wiki-produce” skill，减少路由时对项目规范的隐性依赖
