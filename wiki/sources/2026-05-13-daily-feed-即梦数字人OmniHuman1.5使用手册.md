# 即梦数字人新模型 OmniHuman 1.5 使用手册

## 概述

OmniHuman 1.5 是即梦推出的全新影视级数字人模型。比起传统数字人，新模型下角色更像"数字演员"——角色能走位、能演戏、镜头能运动，还十分听话。

### 核心差异

| 传统数字人 | OmniHuman 1.5 |
|------------|---------------|
| 仅能做到对口型 | 能理解音频语义 |
| 生成动作随机 | 动作与音频内容相关 |
| 固定站位 | 角色能走位 |
| 固定镜头 | 镜头能运动 |

---

## 核心特性与亮点

### 🎯 理解音频
角色能做出与音频语义相关的动作
- 说到"吞下蓝药丸"，角色立即展示蓝药丸
- 说到"递一下象牙线"时，角色会回头

### 🎬 角色能走动，镜头能运动
支持用户像使用视频生成模型一样控制画面：
- 可输入多个动作指令
- 控制角色走位、转身、动作
- 控制运镜、背景元素

### 🎭 生动的情绪演绎
模型能识别并演绎音频和台词中的情绪，尤其在对白场景具有更强的演技效果

### 👥 多人场景支持
可指定画面中某一人说话，其他人物也有自然动态

### 🎨 多样风格和主体支持
支持更多风格和形象主体，包括猫猫狗狗等各色动物

## 基础参数

| 参数 | 限制 |
|------|------|
| 输入图片格式 | JPG, PNG 等 |
| 图片大小限制 | < 5MB, < 4096×4096 |
| 音频时长 | 推荐 ≤ 15 秒，最大 30 秒 |
| 支持分辨率 | 720P, 1080P |
| 生成模式 | 快速模式，大师模式 |
| 支持语言 | 不限，中、英、日等常见语种表现更佳 |

## 提示词编写指南

### 💡 核心原则

1. **把编写提示词当成讲故事**：使用连贯自然的自然语言，尽可能减少孤立词汇的堆砌
2. **只描述动态的事件**：图片中已经包含的静态特征无需描述
3. **遵循清晰、不矛盾、少否定的原则**：使用具体而非抽象的描述

### 💎 最佳实践模板

**推荐结构**：
```
镜头运动 + 说话角色情绪 + 说话状态（说话/哭泣/唱歌/...） + 具体动作 + （可选）背景事件/其他角色的动作
```

**完整示例**：
```
镜头从侧面缓慢推进到正面中景。年轻女子坐在窗边，心情平静，轻轻端起咖啡杯，微笑着对镜头说话。旁边的男孩悄悄看着她，时不时转向镜头笑笑。背景中灯光柔和地闪烁。
```

**注意**：在提示词中将"角色xxx说话""角色xxx唱歌"写出，有助于提高说话表现

## 控制技巧

### 连续动作及走位控制
通过"先"、"然后"等词描述动作顺序，实现复杂的动作编排

### 先说话再做动作/先做动作再说话
在说话前后也能插入动作

### 多角色动作控制
多人场景着重描述角色间的互动方式

### 镜头运动控制
- 精确控制镜头的移动方式和节奏
- 通过描述运镜结束时的镜头状态，精准控制运镜快慢与结束位置
- 使用类似"迅速"这样的词汇，能提高运镜响应率

### 情绪层次控制&微表情控制
结合音频内容描述细腻的情绪变化

### 特效/无中生有/增加画面元素
参考图里没有出现的元素，可以用提示词添加

### 镜头焦点控制
对于前后景分别存在不同角色的场景，可以通过提示词控制镜头移焦

### 环境互动描述
让角色与环境产生自然的互动关系

## 注意事项

### ✅ 推荐做法
- 视频清晰度高度依赖输入的图片！尽可能上传清晰度更高的图片
- 单次生成效果具随机性，复杂场景可多次抽卡尝试
- 输入提示词效果不佳，也可以尝试不输提示词看看

### ⚠️ 效果问题规避
- **结构稳定性**：15秒以内较好，15秒后可能出现衰退
- **人脸占比**：过小会偶现口型不动现象，尽可能规避超远景
- **一致性变化**：人物长时间出镜再入镜后易出现一致性变化
- **极端姿势**：极端姿势或角度效果可能不佳

## 常见问题解答

**Q: 如何指定角色说话？**
上传图片后稍等片刻，在「角色说」处点击切换说话角色

**Q: 如何让所有角色一起说话？**
选择「全部角色」，即刻生成所有角色说一样的内容的视频（合唱等场景）

**Q: 提示词不生效怎么办？**
- 确保提示词描述清晰具体
- 避免矛盾或过于复杂的指令
- 尝试调整动作时序描述
- 可以分步骤细化描述
