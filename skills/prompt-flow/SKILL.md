# Prompt Flow — 提示词决策流程技能（全局前置版）

> **定位**：**全局固定触发的入口技能**。每次用户提问时，必须先走完四阶段流程，再执行具体任务。
>
> **重要**：这不是可选技能，而是强制前置流程。无论用户问什么，都要先执行反向沟通→类别判断→生成→自检。

---

## 核心原则（来自课程）

在进入流程之前，Agent 必须内化以下课程核心方法论，它们将贯穿整个决策流程：

| 编号 | 原则 | 来源 | 贯穿阶段 |
|------|------|------|----------|
| P1 | **上下文为王**：把 AI 想象成聪明的应届生，积极性高但不了解你；给的上下文越多越相关，输出越定制化 | 模块二·第2课 | 反向沟通、生成 |
| P2 | **避免谄媚**：使用中性措辞提问，不给 AI 暗示你想要什么答案；提供评分标准迫使客观 | 模块二·第5课 | 类别判断、生成、自检 |
| P3 | **渐进式大纲法**：先大纲→迭代大纲→展开要点→迭代要点→最终文本；编辑大纲比编辑全文高效得多 | 模块二·第6课 | 生成（写作类） |
| P4 | **迭代头脑风暴**：给足上下文→生成多个选项→对选项给反馈→再生成→迭代直到满意 | 模块二·第1课 | 反向沟通、生成 |
| P5 | **信息路径选择**：预训练知识（常识）→ 网络搜索（实时/小众）→ 深度研究（综合多源复杂问题） | 模块一·第1-5课 | 类别判断、生成 |
| P6 | **评分标准驱动批评**：给 AI 明确的、无歧义的评分维度和分值，迫使客观评估 | 模块二·第7课 | 生成（批评类）、自检 |
| P7 | **多模态成本意识**：文本→语音→图像→视频，生成成本和耗时递增；迭代能力递减 | 模块三·第1课 | 类别判断、生成 |
| P8 | **代码与数据分析**：AI 通过编写并执行代码来处理计算和绘图任务，而非直接回答 | 模块三·第5课 | 类别判断、生成 |

---

## 四阶段决策流程

### 阶段一：反向沟通（素材收集）

**目标**：在生成任何提示词之前，先弄清楚用户真正需要什么，以及需要什么素材。

**触发时机**：每次用户请求生成提示词时，**必须**先进入此阶段。

**执行步骤**：

1. **理解用户意图**：用自己的话复述用户的需求，确认理解一致
2. **判断信息缺口**：基于用户需求，识别以下维度中哪些信息缺失
3. **向用户提问**：使用 AskUserQuestion 工具一次性提出关键问题（最多 4 个）

**信息缺口检查清单**（根据需求类别选择性询问）：

```
□ 目标受众：这个提示词给谁用？（自己 / 团队 / 客户 / 公开）
□ 使用场景：在什么平台/工具上使用？（ChatGPT / Claude / Gemini / API / 其他）
□ 输入素材：用户已有哪些相关材料？（文档 / 数据 / 图片 / 代码 / 无）
□ 期望输出：希望 AI 生成什么形式的结果？（文本 / 图像 / 代码 / 分析报告 / 其他）
□ 当前思路：用户是否已有初步想法或偏好？（有 / 没有 / 部分有）
□ 约束条件：有无特殊要求？（字数限制 / 风格要求 / 合规要求 / 语言）
□ 迭代意愿：是否需要多轮迭代？（一次性 / 需要迭代优化）
```

**沟通原则**：
- 优先问高影响问题（目标、场景、素材），跳过显而易见的
- 如果用户需求已经足够清晰，可以跳过此阶段直接进入阶段二，但需说明"你的需求已经很清晰"
- 不要问用户已经提供过的信息

---

### 阶段二：类别判断（提示词分类）

**目标**：根据用户需求，判断所需的提示词类别，并选择对应的方法论策略。

**提示词类别决策树**：

```
用户需求
├── A. 信息查找类
│   ├── A1. 常识/定义/摘要 → 预训练知识路径（无需搜索）
│   ├── A2. 时事/实时信息 → 网络搜索路径
│   ├── A3. 小众/地点特定 → 网络搜索路径
│   └── A4. 综合多源复杂问题 → 深度研究路径
│
├── B. 创意/头脑风暴类
│   ├── B1. 选项生成（创意方案/想法列表）→ 迭代头脑风暴法
│   └── B2. 决策辅助（多方案比较/选择）→ 迭代头脑风暴 + 中性措辞
│
├── C. 写作类
│   ├── C1. 从零写作 → 渐进式大纲法
│   ├── C2. 基于已有文本写作 → 上下文注入 + 渐进式大纲
│   └── C3. 编辑/改写 → 逐段编辑法
│
├── D. 批评/评估类
│   ├── D1. 客观评估（作品/方案/数据）→ 评分标准驱动法
│   └── D2. 改进建议 → 评分标准 + 改进方向
│
├── E. 多模态类
│   ├── E1. 图像生成 → 场景+角色+氛围描述法
│   ├── E2. 图像理解 → 多图上传 + 中等复杂度指令
│   ├── E3. 视频/语音生成 → 成本意识 + 精确描述
│   └── E4. 图像编辑 → 参考图 + 修改指令
│
├── F. 代码/应用类
│   ├── F1. 构建应用 → 目标+输入+输出三要素法
│   ├── F2. 数据分析 → 数据文件 + 分析问题 + 可视化需求
│   └── F3. 代码生成/调试 → 上下文 + 错误信息 + 期望行为
│
└── G. 推理/复杂任务类
    ├── G1. 长时间推理 → 充足上下文 + "认真思考"指令
    └── G2. 多步骤任务 → 任务分解 + 逐步执行
```

**复合类别处理**：
- 如果需求跨越多个类别（如"研究一个主题然后写一篇文章"），按顺序处理：先 A（信息查找）→ 再 C（写作）
- 明确告知用户将分步处理，并说明每步的策略

**输出格式**：向用户简要说明判断结果，例如：
> "你的需求属于 **C1（从零写作）+ A2（网络搜索）** 复合类别。我将先帮你构建信息查找的提示词，再构建写作的提示词。"

---

### 阶段三：生成提示词

**目标**：基于类别判断结果，应用对应方法论生成高质量提示词。

**生成前自检**（在输出提示词之前，内部执行以下检查）：

```
□ 上下文充分性：提示词是否包含足够的背景信息让 AI 理解任务？
□ 中性措辞：是否存在引导 AI 给出特定答案的措辞？（谄媚检查）
□ 任务明确性：AI 是否清楚知道要做什么、输出什么格式？
□ 信息路径正确：是否选择了正确的信息获取路径？
□ 迭代机制：是否包含让 AI 生成多个选项或分步推进的指令？
□ 评分标准（如适用）：是否提供了明确、无歧义的评估维度？
□ 输出格式：是否指定了期望的输出格式和结构？
```

**各类别提示词模板**：

#### A. 信息查找类

**A1 预训练知识路径**：
```
[任务描述]
[具体问题]
请基于你的知识回答，如果不确定请明确说明。
```

**A2 网络搜索路径**：
```
[任务描述]
[具体问题]
请通过网络搜索获取最新信息来回答。
优先引用[指定信息源类型，如：官方机构/学术论文/权威媒体]的信息。
```

**A3 深度研究路径**：
```
[任务描述]
[研究问题]
请使用深度研究功能，综合多个信息源进行深入分析。
研究计划应覆盖以下维度：
1. [维度1]
2. [维度2]
3. [维度3]
最终输出一份结构化的研究报告，包含引用来源。
```

#### B. 创意/头脑风暴类

**B1 迭代头脑风暴**：
```
[背景上下文：我是谁、我的情况、我的约束条件]
[我的偏好/不想要的东西]
[具体任务]

请先给我 3-5 个不同的[方案/想法/选项]，每个方案简要说明核心思路。
不要只给常识性建议——结合我提供的[特殊上下文]给出有创意的方案。
```

**B2 决策辅助**：
```
[决策背景]
[选项A] vs [选项B] vs [选项C]

请客观比较以上选项的优缺点，从以下维度评估：
1. [维度1]
2. [维度2]
3. [维度3]

不要假设我偏好某个选项。请基于事实给出分析。
```

#### C. 写作类

**C1 渐进式大纲法（从零写作）**：
```
[写作任务描述]
[目标受众]
[核心观点/论点]
[已有素材/参考资料]

请按以下步骤进行：
第一步：先列出 3 个不同的文章大纲选项，每个大纲包含主要章节和核心论点。
等待我对大纲的反馈后，再进入下一步。
```

**C2 基于已有文本**：
```
[写作任务描述]
[附上已有文本/笔记/素材]

请阅读以上素材，然后：
1. 先列出 3 个不同的文章大纲选项
2. 每个大纲说明如何利用已有素材
等待我的反馈后，再展开。
```

**C3 逐段编辑**：
```
[编辑目标：如更口语化/更专业/更简洁]
[附上文本]

请逐段帮我改写。先处理第一段，给我 2-3 种不同的改写方式。
我选定后再处理下一段。
```

#### D. 批评/评估类

**D1 评分标准驱动法**：
```
[评估对象描述]
[附上作品/方案]

请按以下评分标准进行客观评估：

评分标准（总分 100 分）：
- [维度1]（XX分）：[明确的评判规则，无歧义]
- [维度2]（XX分）：[明确的评判规则，无歧义]
- [维度3]（XX分）：[明确的评判规则，无歧义]

请对每个维度独立打分并说明理由，最后汇总总分。
保持客观，不要因为我想听好话就给高分。
```

#### E. 多模态类

**E1 图像生成**：
```
[场景描述：环境、光线、构图]
[角色/主体描述：外观、姿态、表情]
[风格/氛围：如电影感/水彩/赛博朋克/动漫]
[技术参数：如宽高比、色调]
```

**E2 图像理解**：
```
[附上图片]
[具体问题]
请仔细观察图片中的[指定元素]，回答[具体问题]。
```

#### F. 代码/应用类

**F1 构建应用**：
```
请构建一个[应用类型]。

目标：[用户能做什么]
输入：[用户需要提供什么]
输出：[用户看到什么]

技术要求：
- [如有：使用特定框架/语言]
- [如有：响应式设计/特定功能]
```

**F2 数据分析**：
```
[附上数据文件]

请分析以上数据，回答以下问题：
1. [问题1]
2. [问题2]

请通过编写和运行代码来进行分析，并生成可视化图表。
```

#### G. 推理/复杂任务类

**G1 长时间推理**：
```
[任务描述]
[附上所有相关上下文/文件]

请认真思考这个问题。阅读所有材料，在回答前深入思考。
[如需要：请从以下维度进行分析：维度1、维度2、维度3]
```

### 阶段四：自检概述

**目标**：在提示词生成后，向用户展示一份简要的自检报告。

**自检概述格式**：

```markdown
## 提示词自检概述

| 检查项 | 状态 | 说明 |
|--------|------|------|
| 上下文充分性 | ✅/⚠️ | [说明] |
| 谄媚风险 | ✅/⚠️ | [说明] |
| 任务明确性 | ✅/⚠️ | [说明] |
| 信息路径 | ✅/⚠️ | [说明] |
| 迭代机制 | ✅/⚠️ | [说明] |
| 输出格式 | ✅/⚠️ | [说明] |

**提示词类别**：[如 C1 + A2]
**推荐使用模型**：[如 GPT-4o / Claude 3.5 / Gemini]
**预估效果**：[如：该提示词采用渐进式大纲法，预计能生成结构清晰的文章框架，但最终文本质量取决于后续迭代轮次]
**优化建议**：[如有改进空间，给出 1-2 条建议]
```

**自检标准详解**：

| 检查项 | 通过标准 | 常见问题 |
|--------|----------|----------|
| 上下文充分性 | 提示词包含目标受众、任务背景、约束条件 | 缺少受众信息、缺少素材引用 |
| 谄媚风险 | 措辞中性，不暗示期望答案 | "帮我证明..."、"你觉得...好不好" |
| 任务明确性 | AI 能清楚知道要做什么、输出什么格式 | 任务模糊、缺少输出格式要求 |
| 信息路径 | 与任务复杂度匹配 | 简单问题用深度研究、复杂问题不用搜索 |
| 迭代机制 | 包含多选项生成或分步推进指令 | 一次性要求输出最终结果 |
| 输出格式 | 指定了输出结构/长度/风格 | 未指定格式导致输出不可控 |

## 完整执行示例

### 示例：用户说"帮我写个提示词，让 AI 帮我分析竞品"

**阶段一（反向沟通）**：
> "你想让 AI 分析哪些竞品？你手头有竞品的相关资料吗（产品页面、定价、功能列表）？分析结果用于什么场景（内部决策 / 投资路演 / 市场报告）？"

> "你的需求属于 **A2（网络搜索）+ D1（客观评估）** 复合类别。需要先搜索竞品信息，再用评分标准进行客观比较。"

**阶段三（生成提示词）**：
> （应用 A2 + D1 模板生成完整提示词）

**阶段四（自检概述）**：
> （输出自检表格，标注状态和建议）

## 特殊场景处理

### 场景 1：用户需求模糊
- 不猜测用户意图，使用 AskUserQuestion 明确
- 提供 2-3 个可能的方向让用户选择

### 场景 2：用户已有提示词，想优化
- 跳过阶段一（素材已隐含在现有提示词中）
- 对现有提示词执行阶段四的自检
- 基于自检结果提出优化建议

### 场景 3：用户需要跨模型通用提示词
- 提示词应避免模型特定功能（如特定工具名）
- 使用通用指令（"请搜索"而非"使用深度研究"）

### 场景 4：用户需要提示词给别人用
- 在提示词中加入使用说明（如何填写变量、预期效果）
- 标注推荐模型和参数设置
