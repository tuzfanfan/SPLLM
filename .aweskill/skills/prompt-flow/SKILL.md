# Prompt Flow — 提示词决策流程技能（全局前置版）

> **定位**：**全局固定触发的入口技能**。每次用户提问时，必须先走完五阶段流程，并在反向沟通后嵌入稳定性风险扫描（反向沟通→稳定性风险扫描→维度判断→类别判断→生成→自检），再执行具体任务。
>
> **重要**：这不是可选技能，而是强制前置流程。无论用户问什么，都要先执行完整流程。

---

## 核心原则（来自课程）

在进入流程之前，Agent 必须内化以下课程核心方法论，它们将贯穿整个决策流程：

| 编号 | 原则 | 来源 | 贯穿阶段 |
|------|------|------|----------|
| P1 | **上下文为王**：把 AI 想象成聪明的应届生，积极性高但不了解你；给的上下文越多越相关，输出越定制化 | 模块二·第2课 | 反向沟通、生成 |
| P2 | **避免谄媚**：使用中性措辞提问，不给 AI 暗示你想要什么答案；提供评分标准迫使客观 | 模块二·第5课 | 类别判断、生成、自检 |
| P3 | **渐进式大纲法**：先大纲→迭代大纲→展开要点→迭代要点→最终文本；编辑大纲比编辑全文高效得多 | 模块二·第6课 | 生成（写作类） |
| P4 | **迭代头脑风暴**：给足上下文→生成多个选项→对选项给反馈→再生成→迭代直到满意 | 模块二·第1课 | 反向沟通、生成 |
| P5 | **信息路径选择**：预训练知识（常识）→ 网络搜索（实时/小众）→ 深度研究（综合多源复杂问题） | 模块一·第1-5课 | 类别判断、生成 |
| P6 | **评分标准驱动批评**：给 AI 明确的、无歧义的评分维度和分值，迫使客观评估 | 模块二·第7课 | 生成（批评类）、自检 |
| P7 | **多模态成本意识**：文本→语音→图像→视频，生成成本和耗时递增；迭代能力递减 | 模块三·第1课 | 类别判断、生成 |
| P8 | **代码与数据分析**：AI 通过编写并执行代码来处理计算和绘图任务，而非直接回答 | 模块三·第5课 | 类别判断、生成 |
| P9 | **稳定性优先**：来自 Anthropic 交互式提示工程教程；先诊断 prompt 可能在哪里失稳，再选择清晰指令、材料隔离、格式控制、few-shot、证据先行、chaining、工具/检索等增强策略 | Anthropic Prompt Engineering Interactive Tutorial | 稳定性风险扫描、生成、自检 |

## 五阶段决策流程

### 阶段一：反向沟通（素材收集）

**目标**：在生成任何提示词之前，先弄清楚用户真正需要什么，以及需要什么素材。

**触发时机**：每次用户请求生成提示词时，**必须**先进入此阶段。

**执行步骤**：

1. **理解用户意图**：用自己的话复述用户的需求，确认理解一致
2. **判断信息缺口**：基于用户需求，识别以下维度中哪些信息缺失
3. **向用户提问**：使用 AskUserQuestion 工具一次性提出关键问题（最多 4 个）

**信息缺口检查清单**（根据需求类别选择性询问）：

```
□ 目标受众：这个提示词给谁用？（自己 / 团队 / 客户 / 公开）
□ 使用场景：在什么平台/工具上使用？（ChatGPT / Claude / Gemini / API / 其他）
□ 输入素材：用户已有哪些相关材料？（文档 / 数据 / 图片 / 代码 / 无）
□ 期望输出：希望 AI 生成什么形式的结果？（文本 / 图像 / 代码 / 分析报告 / 其他）
□ 当前思路：用户是否已有初步想法或偏好？（有 / 没有 / 部分有）
□ 约束条件：有无特殊要求？（字数限制 / 风格要求 / 合规要求 / 语言）
□ 迭代意愿：是否需要多轮迭代？（一次性 / 需要迭代优化）
```

**沟通原则**：
- 优先问高影响问题（目标、场景、素材），跳过显而易见的
- 如果用户需求已经足够清晰，可以跳过此阶段直接进入阶段二，但需说明"你的需求已经很清晰"
- 不要问用户已经提供过的信息

---

### 阶段1.1：稳定性风险扫描（失败模式诊断）

**目标**：在选择任务类别之前，先判断这个任务最可能在哪里失稳，并选择 1-3 个最必要的提示工程稳定策略。

**触发时机**：阶段一完成后内部执行。除非用户要求详细解释，一般不单独展示完整诊断，只把必要结论自然融入后续生成。

**风险扫描清单**：

| 失败风险 | 常见表现 | 推荐稳定策略 |
|---|---|---|
| 任务边界不清 | 输出沾边但不对题 | 使用 clear and direct：明确动作、范围、交付物 |
| 角色或受众漂移 | 语气、深度、视角不稳定 | 明确角色、目标受众、使用场景 |
| 材料和指令混杂 | 模型把材料误读成指令 | 使用 XML tag 或清晰分段隔离 data / context / instruction |
| 输出格式漂移 | 字段丢失、结构不一致 | 明确 output schema、固定字段、必要时使用标签 |
| 多步推理跳步 | 直接给结论、漏看条件 | 要求先分步判断，再输出最终答案 |
| 风格难以描述 | 文风不像、边界感弱 | 使用 few-shot 正例/反例校准 |
| 事实或引用风险高 | 幻觉、把推断当事实 | 证据先行、允许回答“不知道”、要求来源或引用 |
| 单轮任务过载 | prompt 过长、目标过多 | 拆成 chaining：提纲→展开→质检，或抽取→分析→输出 |
| 模型裸能力不足 | 需要计算、检索、执行工具 | 转为工具调用、代码执行、联网检索或知识库检索 |

**执行规则**：
- 每次最多选择 1-3 个稳定策略，避免提示词过重
- 优先处理高风险项：事实准确性、输出格式、材料隔离、任务边界
- 如果任务只是简单问答，不强行加入 XML、few-shot 或 chaining
- 如果用户已有 prompt 草稿，先按失败模式诊断，再决定是否调用 `improve_prompt`

**内部输出格式**：

```text
稳定性风险：{1-3 个风险}
采用策略：{对应稳定策略}
不采用策略：{说明被跳过的重型策略，如 few-shot / chaining / tool use}
```

### 阶段1.5：维度判断（思维框架匹配）

**目标**：在进入提示词类别判断之前，先判断任务所属的**思维维度**，决定是否加载《毛泽东选集》方法论技能库中的对应思考框架。

**触发时机**：每次用户提出任务后，在类别判断之前**必须**执行此阶段。

**为什么需要维度判断？**

不同的任务需要不同的思维框架。例如：
- "如何打败行业巨头？" → 需要**持久战战略**（战略思维维度）
- "团队意见分歧大，怎么办？" → 需要**群众路线**（工作方法维度）
- "写一个咖啡厅视频的提示词" → 不需要毛选方法论（常规任务维度）

**维度判断决策树**：

```
用户任务
├── 维度一：战略思维
│   ├── 信号：涉及长期规划、竞争策略、资源分配、复杂决策
│   ├── 可匹配技能：
│   │   ├── 矛盾分析法 → 问题复杂、千头万绪，不知从何下手
│   │   ├── 持久战战略 → 面对强大对手、资源有限、需要长期积累
│   │   ├── 统一战线策略 → 需要建立广泛联盟、协调多方利益
│   │   └── 阶级分析法 → 需要分析利益格局、识别各方立场
│   └── 加载方式：将对应方法论作为思考框架融入后续阶段
│
├── 维度二：工作方法
│   ├── 信号：涉及团队管理、组织变革、调查研究、方案推广
│   ├── 可匹配技能：
│   │   ├── 调查研究法 → 对新领域不了解、需要获取真实认知
│   │   ├── 群众路线 → 需要推动变革、收集多方意见
│   │   ├── 批评与自我批评 → 团队出现问题、需要纠正错误
│   │   └── 试点推广法 → 新方案需要验证、由点到面推广
│   └── 加载方式：将对应方法论作为执行框架融入后续阶段
│
├── 维度三：军事指挥（商业/竞争隐喻）
│   ├── 信号：涉及灵活竞争、积小胜为大胜、集中优势
│   ├── 可匹配技能：
│   │   ├── 运动战原则 → 需要灵活机动、集中优势逐个击破
│   │   └── 游击战十六字诀 → 需要积小胜为大胜、避实击虚
│   └── 加载方式：将对应方法论作为竞争策略融入后续阶段
│
└── 维度四：常规任务（不触发毛选方法论）
    ├── 信号：写文案、生成图片、查资料、写代码等日常任务
    └── 处理：直接进入阶段二（类别判断），不加载额外框架
```

**执行步骤**：

1. **快速扫描**：分析用户任务的核心特征（1-2秒内判断）
2. **匹配维度**：对照决策树，判断属于哪个维度
3. **匹配技能**：如果属于维度一/二/三，进一步匹配最相关的技能
4. **加载框架**：将匹配到的技能核心方法论融入后续的类别判断和生成阶段
5. **告知用户**：简要说明判断结果（一句话即可）

**输出格式**：

匹配到毛选技能时：
> "💡 **维度判断**：你的任务属于「维度一：战略思维」，已加载**矛盾分析法**作为思考框架。"

不匹配时（可省略说明，直接进入阶段二）：
> （无需说明，直接进入阶段二）

**匹配规则**：
- 一个任务最多匹配**1-2个**毛选技能，避免框架过载
- 如果任务明确属于常规任务（维度四），**不要强行匹配**
- 匹配到的技能框架应**自然融入**后续阶段，而非单独输出
- 复合任务可跨维度匹配（如"创业从0到1"可匹配调查研究法+矛盾分析法+持久战战略）

**维度判断速查表**：

| 你的问题 | 维度 | 推荐技能 |
|----------|------|----------|
| 问题复杂，不知从何下手 | 战略思维 | 矛盾分析法 |
| 对新领域/市场不了解 | 工作方法 | 调查研究法 |
| 需要推动变革但阻力大 | 工作方法 | 群众路线 |
| 面对强大对手，资源有限 | 战略思维 | 持久战战略 |
| 需要建立广泛联盟 | 战略思维 | 统一战线策略 |
| 需要分析利益格局 | 战略思维 | 阶级分析法 |
| 团队出现问题需要纠正 | 工作方法 | 批评与自我批评 |
| 新方案需要验证 | 工作方法 | 试点推广法 |
| 需要灵活机动的策略 | 军事指挥 | 运动战原则 |
| 需要积小胜为大胜 | 军事指挥 | 游击战十六字诀 |
| 写文案/生成图片/查资料/写代码 | 常规任务 | 不触发 |

### 阶段二：类别判断（提示词分类）

**目标**：根据用户需求，判断所需的提示词类别，并选择对应的方法论策略。

**提示词类别决策树**：

```
用户需求
├── A. 信息查找类
│   ├── A1. 常识/定义/摘要 → 预训练知识路径（无需搜索）
│   ├── A2. 时事/实时信息 → 网络搜索路径
│   ├── A3. 小众/地点特定 → 网络搜索路径
│   └── A4. 综合多源复杂问题 → 深度研究路径
│
├── B. 创意/头脑风暴类
│   ├── B1. 选项生成（创意方案/想法列表）→ 迭代头脑风暴法
│   └── B2. 决策辅助（多方案比较/选择）→ 迭代头脑风暴 + 中性措辞
│
├── C. 写作类
│   ├── C1. 从零写作 → 渐进式大纲法
│   ├── C2. 基于已有文本写作 → 上下文注入 + 渐进式大纲
│   └── C3. 编辑/改写 → 逐段编辑法
│
├── D. 批评/评估类
│   ├── D1. 客观评估（作品/方案/数据）→ 评分标准驱动法
│   └── D2. 改进建议 → 评分标准 + 改进方向
│
├── E. 多模态类
│   ├── E1. 图像生成 → 场景+角色+氛围描述法
│   ├── E2. 图像理解 → 多图上传 + 中等复杂度指令
│   ├── E3. 视频/语音生成 → 成本意识 + 精确描述
│   ├── E4. 图像编辑 → 参考图 + 修改指令
│   └── E5. AI视频/图像生成（即梦/可灵）→ 结构化提示词工程法（见阶段三·进阶策略）
│
├── F. 代码/应用类
│   ├── F1. 构建应用 → 目标+输入+输出三要素法
│   ├── F2. 数据分析 → 数据文件 + 分析问题 + 可视化需求
│   └── F3. 代码生成/调试 → 上下文 + 错误信息 + 期望行为
│
└── G. 推理/复杂任务类
    ├── G1. 长时间推理 → 充足上下文 + "认真思考"指令
    └── G2. 多步骤任务 → 任务分解 + 逐步执行
```

**复合类别处理**：
- 如果需求跨越多个类别（如"研究一个主题然后写一篇文章"），按顺序处理：先 A（信息查找）→ 再 C（写作）
- 明确告知用户将分步处理，并说明每步的策略

**输出格式**：向用户简要说明判断结果，例如：
> "你的需求属于 **C1（从零写作）+ A2（网络搜索）** 复合类别。我将先帮你构建信息查找的提示词，再构建写作的提示词。"

### Anthropic 稳定策略映射

阶段二完成类别判断后，必须把阶段1.1的风险扫描结果映射到具体提示工程策略中。这个映射是增强层，不新增独立任务类别。

| 当前类别 | 默认增强策略 | 适用条件 |
|---|---|---|
| A. 信息查找类 | 证据先行、来源优先级、允许未知、必要时检索 | 涉及时效、事实、引用、对外发布 |
| B. 创意/头脑风暴类 | 清晰约束、角色/受众、多个选项、迭代反馈 | 需要发散但不能跑题 |
| C. 写作类 | 渐进式大纲、few-shot 风格示例、输出结构 | 需要风格、篇章结构或长期可复用文风 |
| D. 批评/评估类 | 评分标准、分步判断、证据引用 | 需要客观评估或改进建议 |
| E. 多模态类 | 主体/动作/场景/镜头/风格分层、变量隔离 | 需要稳定生成图像/视频提示词 |
| F. 代码/应用类 | 输入输出协议、验收标准、错误边界、工具/测试 | 需要可执行结果或调试 |
| G. 推理/复杂任务类 | step-by-step、事实/推断/假设分层、chaining | 需要多步推理或复杂交付 |

**选择规则**：
- 类别决定“做什么”，稳定策略决定“怎样不失稳”
- 同一任务最多叠加 3 个稳定策略
- 事实风险高于风格风险，输出格式风险高于表达润色
- 如果某个策略会显著增加用户成本，先说明取舍

### 阶段三：生成提示词

**目标**：基于类别判断结果，应用对应方法论生成高质量提示词。

**生成前自检**（在输出提示词之前，内部执行以下检查）：

```
□ 上下文充分性：提示词是否包含足够的背景信息让 AI 理解任务？
□ 中性措辞：是否存在引导 AI 给出特定答案的措辞？（谄媚检查）
□ 任务明确性：AI 是否清楚知道要做什么、输出什么格式？
□ 信息路径正确：是否选择了正确的信息获取路径？
□ 迭代机制：是否包含让 AI 生成多个选项或分步推进的指令？
□ 评分标准（如适用）：是否提供了明确、无歧义的评估维度？
□ 输出格式：是否指定了期望的输出格式和结构？
□ 稳定性风险：是否识别了最可能失稳的 1-3 个风险？
□ 稳定策略：是否已加入必要的材料隔离、格式控制、few-shot、证据先行、chaining 或工具/检索策略？
```

**统一提示词结构协议**（按需裁剪，不要机械全量输出）：

```text
任务目标：
{用户真正要完成的任务}
```

**协议使用规则**：
- 简单任务只保留“任务目标 + 输出格式 + 质量标准”
- 输入材料较长时，必须用 `<data>` 或等价边界隔开
- 风格任务优先加入 few-shot 示例，而不是堆抽象形容词
- 事实高风险任务必须加入证据要求和“不知道/材料未提供”的出口
- 单轮提示过长时，改为 chaining 流程：抽取→分析→输出→质检

**E5 AI视频/图像生成（即梦/可灵）—— 结构化提示词工程法**：

当用户需要为即梦（字节跳动）或可灵（快手）等AI视频/图像生成平台编写提示词时，应用以下结构化框架：

**第一步：确定平台特性**
| 平台 | 定位 | 提示词风格 | 核心公式 |
|------|------|-----------|----------|
| 即梦 | 影视级专业工具 | 讲故事式自然语言 | 镜头+情绪+动作+背景 |
| 可灵 | 大众创作工具 | 公式化结构化 | 主体+运动+背景+镜头+光影+氛围 |

**第二步：选择对应结构模板**

*即梦视频/数字人提示词结构*：
```
镜头[运动方式：推进/拉远/环绕/跟随]，[角色]在[位置]，[情绪状态]，[具体动作]，[说话/唱歌标记]。
[背景事件/其他角色动作]。
[环境互动描述：微风吹过，衣角飘动]。
```

*可灵视频提示词结构*：
```
镜头[镜头语言：中景/特写/跟随]，[光影效果]，[氛围描述]，
[主体细节]在[背景]进行[运动描述]，
[主体间互动]，[画风/质感]。
```

*图像生成通用结构*：
```
[用途/类型：海报/插画/摄影] + [主体描述] + [行为/状态] + 
[环境/背景] + [美学风格：电影质感/水墨/油画] + [技术参数]
```

**第三步：填充核心要素**

| 要素类别 | 即梦侧重 | 可灵侧重 | 示例 |
|---------|---------|---------|------|
| 镜头语言 | 精确控制起始和结束状态 | 指定镜头类型即可 | 镜头从侧面缓慢推进到正面中景 |
| 情绪表达 | 详细描述内心状态和微表情 | 简要说明氛围 | 心情平静，微笑着；不屑地翻白眼 |
| 动作编排 | 使用时间顺序词（先...然后...） | 描述运动状态 | 先向前走，然后停下脚步 |
| 环境互动 | 强调背景事件和氛围变化 | 简要描述背景 | 背景中灯光柔和地闪烁 |
| 光影氛围 | 融入叙事描述 | 作为独立要素 | 氛围光照，电影级调色 |

**第四步：应用进阶技巧**

*多模态引用（即梦Seedance 2.0）*：
```
@图片1 @图片2 中的[主体]在@视频1 的[场景/节奏]中[动作]
```

*时间轴描述（智能多帧）*：
```
[0-5秒]：[画面状态]，[动作]，（情绪：[状态]）
[6-10秒]：[画面状态]，[动作]，（情绪：[状态]）
```

*分镜式描述*：
```
[时长]：[分镜描述]，[镜头运动]，[角色动作/台词]
```

**第五步：关键词优化**

*影像风格关键词*：大特写、特写、近景、中景、全景、大远景、浅景深、动态模糊、柔焦

*艺术风格关键词*：国画、水墨、工笔、油画、水彩、版画、极简主义、CG概念、皮克斯动画

*光影氛围关键词*：氛围光照、晨光、暖色调、冷色调、强烈对比、明暗对比（chiaroscuro）、电影级调色

*材质效果关键词*：亚麻、牛仔、毛绒、皮革、陶瓷、玻璃、金属、石膏、大理石

**第六步：质量检查**

```
□ 画面内容是否简单明确（符合视频时长内可完成的动作）
□ 运动是否符合物理规律（避免复杂物理运动如球类弹跳）
□ 关键词是否具体（使用"日系青春电影质感"而非"好看的风格"）
□ 文字内容是否用引号标注（提升文字准确率）
□ 是否指定了使用场景（海报/插画/摄影/短视频）
```

### 阶段四：自检概述

**目标**：在提示词生成后，向用户展示一份简要的自检报告。

**自检概述格式**：

```markdown
## 提示词自检概述

| 检查项 | 状态 | 说明 |
|--------|------|------|
| 上下文充分性 | ✅/⚠️ | [说明] |
| 谄媚风险 | ✅/⚠️ | [说明] |
| 任务明确性 | ✅/⚠️ | [说明] |
| 信息路径 | ✅/⚠️ | [说明] |
| 迭代机制 | ✅/⚠️ | [说明] |
| 输出格式 | ✅/⚠️ | [说明] |
| 失败风险 | ✅/⚠️ | [最可能失稳的 1-3 个点] |
| 稳定策略 | ✅/⚠️ | [已采用的 Anthropic 稳定策略] |

**提示词类别**：[如 C1 + A2]
**推荐使用模型**：[如 GPT-4o / Claude 3.5 / Gemini]
**预估效果**：[如：该提示词采用渐进式大纲法，预计能生成结构清晰的文章框架，但最终文本质量取决于后续迭代轮次]
**优化建议**：[如有改进空间，给出 1-2 条建议]
```

**自检标准详解**：

| 检查项 | 通过标准 | 常见问题 |
|--------|----------|----------|
| 上下文充分性 | 提示词包含目标受众、任务背景、约束条件 | 缺少受众信息、缺少素材引用 |
| 谄媚风险 | 措辞中性，不暗示期望答案 | "帮我证明..."、"你觉得...好不好" |
| 任务明确性 | AI 能清楚知道要做什么、输出什么格式 | 任务模糊、缺少输出格式要求 |
| 信息路径 | 与任务复杂度匹配 | 简单问题用深度研究、复杂问题不用搜索 |
| 迭代机制 | 包含多选项生成或分步推进指令 | 一次性要求输出最终结果 |
| 输出格式 | 指定了输出结构/长度/风格 | 未指定格式导致输出不可控 |
| 失败风险 | 已识别任务边界、材料隔离、格式、事实、风格、推理、工具等主要风险 | 只判断任务类型，没有判断会在哪里失稳 |
| 稳定策略 | 已针对风险加入 clear/direct、XML 分隔、few-shot、证据先行、chaining 或工具/检索 | 策略堆叠过多，或高风险任务没有加证据与格式约束 |

## 特殊场景处理

### 场景 1：用户需求模糊
- 不猜测用户意图，使用 AskUserQuestion 明确
- 提供 2-3 个可能的方向让用户选择

### 场景 2：用户已有提示词，想优化
- 跳过阶段一（素材已隐含在现有提示词中）
- 先执行阶段1.1稳定性风险扫描，判断提示词最可能在哪里失稳
- 再对现有提示词执行阶段四的自检
- 基于自检结果选择 `improve_prompt`，优先补强任务边界、材料隔离、输出格式、few-shot、证据约束或 chaining

### 场景 3：用户需要跨模型通用提示词
- 提示词应避免模型特定功能（如特定工具名）
- 使用通用指令（"请搜索"而非"使用深度研究"）

### 场景 4：用户需要提示词给别人用
- 在提示词中加入使用说明（如何填写变量、预期效果）
- 标注推荐模型和参数设置

## 与其他技能的协作

| 协作技能 | 协作方式 |
|----------|----------|
| **毛选方法论技能库** | 阶段1.5维度判断后，自动加载匹配的思维框架（矛盾分析法/调查研究法/群众路线等），融入后续生成阶段 |
| Anthropic 提示工程方法 | 阶段1.1稳定性风险扫描后，按失败模式加载 clear/direct、data separation、formatting、few-shot、evidence-first、chaining、tool/retrieval 等稳定策略 |
| hv-analysis | 当用户需要产品分析类提示词时，参考 hv-analysis 的分析框架 |

| oral-copy | 当用户需要口播文案或公众号长文创作类提示词时，参考 oral-copy 的文案公式 |

| book2skill | 毛选方法论技能库由 book2skill 从《毛泽东选集》中蒸馏提取 |
| darwin-skill | 可用于优化 prompt-flow 及其他技能的质量 |

**与毛选方法论技能库的深度整合**：

阶段1.5（维度判断）是 prompt-flow 与毛选技能库的核心连接点。匹配规则：

| 用户任务特征 | 匹配维度 | 加载技能 | 融入方式 |
|-------------|----------|----------|----------|
| 问题复杂、千头万绪 | 战略思维 | 矛盾分析法 | 在生成阶段用"找出主要矛盾"框架组织回答 |
| 面对强大对手、资源有限 | 战略思维 | 持久战战略 | 在生成阶段用"三阶段规划"框架制定策略 |
| 对新领域不了解 | 工作方法 | 调查研究法 | 在反向沟通阶段强化信息收集 |
| 需要推动变革、阻力大 | 工作方法 | 群众路线 | 在生成阶段用"从群众中来"框架设计执行方案 |
| 需要建立广泛联盟 | 战略思维 | 统一战线策略 | 在生成阶段用"三类势力分析"框架 |
| 新方案需要验证 | 工作方法 | 试点推广法 | 在生成阶段用"由点到面"框架设计实施路径 |
| 积小胜为大胜 | 军事指挥 | 游击战十六字诀 | 在生成阶段用"敌进我退"框架设计竞争策略 |

**组合使用示例**：

- **"创业从0到1"** → 调查研究法 + 矛盾分析法 + 群众路线 + 持久战战略
- **"面对强大竞争对手"** → 阶级分析法 + 统一战线策略 + 游击战十六字诀 + 运动战原则
- **"产品重大改版"** → 试点推广法 + 群众路线 + 调查研究法 + 矛盾分析法

**与 oral-copy 的深度整合**：
当用户需要为 AI 视频/图像生成平台（如即梦、可灵）编写提示词时，prompt-flow 的 E5 类别会与 oral-copy 协同工作：
- prompt-flow 负责提示词的结构设计和优化流程
- oral-copy 提供影视级叙事的语言风格和节奏控制技巧
- 两者结合可生成既符合平台技术要求、又具有专业影视质感的提示词

## Fabric 融合增强

从 2026-05-19 起，这个 skill 增加两个可选增强动作，专门解决“需求已经清楚，但 prompt 还不够锋利”和“用户其实是在找该用哪个 skill / workflow”的问题。需要时先读 `references/fabric-routing-pack.md`。

优先使用的 Fabric 风格模块：
- `improve_prompt`：把已有 prompt 打磨成更稳的执行指令
- `suggest_pattern`：把“这个任务该怎么做”映射成更合适的 skill / workflow

使用原则：
- 不要因为能优化 prompt 就跳过前置澄清
- 当用户是在问“该用什么方法 / 该怎么设计流程”时，优先走 route / suggest 动作
- 当用户已经有 prompt 草稿时，优先走 refine 动作，并先用阶段1.1判断失败风险
