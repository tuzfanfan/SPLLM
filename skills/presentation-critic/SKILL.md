# Presentation Critic

## 用途

在一份 deck 做完后，系统地挑出故事、结构、页面和证据层的问题。

## 输出结构

1. `总判断`
2. `叙事问题`
3. `页面问题`
4. `证据问题`
5. `优先修改建议`

## 审查顺序

按这个顺序看，不要一上来盯视觉细节：

1. 这套 deck 到底想说服谁
2. 核心结论是否清楚
3. 页面顺序是否支撑结论
4. 每页是否只推进一个点
5. 证据和图表是否真在证明观点
6. 最后才看视觉负担和可读性

## 重点检查

- 标题是否真的是结论
- 每页是不是只讲一件事
- 页面顺序是否支撑核心叙事
- 图表是否真的在证明观点
- 有没有“看起来很多，但其实没有推进”的页

## 评价方式

- 优先指出会影响理解和说服力的问题
- 先讲严重问题，再讲美化建议
- 每条问题尽量给出改法方向

## 推荐输出模板

- `总判断`
- `P0 严重问题`
- `P1 重要问题`
- `P2 可优化项`
- `优先修改顺序`
- `一页话总结`

## 边界

- 不把所有 deck 都评成“再丰富一点”
- 不只看视觉，要先看论证和叙事
- 如果用户只给了部分页面，要明确说明结论范围有限
